Quick start: a ten-minute tour

Every command on this page is read-only. None of them writes a file, needs root or changes a package, so you can run them on a machine you care about.

1. Ask what works here§

doctor prints one line per check. It is the first thing to run on a new machine, and the first thing to attach to a bug report.

warn means something a feature of this system uses is missing, and the line says what you lose. fail means a command will not work, and the line says why. n/a means the check does not apply here, or an optional part is not installed. A healthy machine shows ok and n/a only. More about doctor.

2. Ask why something is installed§

Pick a package you do not remember installing.

The because line is the chain from this package back to something you asked for. More about why.

3. Ask what changed§

When something broke after a reboot, yapacc timeline --since-boot shows only what changed since the machine last started. More about timeline.

4. Ask what the next upgrade will do§

briefing reads the list of pending updates as of your last repository refresh. It does not refresh on its own. More about briefing.

5. See what an undo would do, without doing it§

--dryrun plans and never applies. On undo it shows the last transaction, the reverse of it, and the native manager's own simulation.

A dry run writes nothing. When an old version is in no local cache, the plan says which archive it would come from, and the download happens only after you have agreed.

More about undo.

6. Housekeeping, still read-only§

None of the three changes anything. Each prints the command you would run yourself. More about them.
