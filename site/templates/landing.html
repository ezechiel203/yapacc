A companion for pacman · apt · dnf · zypper · apk · xbps · pkg

Know what changed. Take it back.

yapacc sits beside the package manager you already use. It tells you why a package is there, what changed since the machine last worked, what the next upgrade will do, and it can undo the last transaction. It replaces nothing and leaves nothing running.

§ 1What it answers

Four questions every system eventually asks.

Your package manager already knows the answers. They are spread over its database, three log files and a mailing list. yapacc reads them where they are and says it in one screen.

i.

Why is this here?

The chain from a library back to the thing you asked for, what still needs it, which repository it came from and how it was verified.

§ 2The rules it keeps

A guest in your system, not a landlord.

Tools that help with packages tend to end up owning them. These seven rules are the reason yapacc does not, and each one can be checked against the code.

  1. Your package manager stays yours.

    yapacc keeps no copy of what the native manager knows. Install or remove anything directly and yapacc is never confused by it.

  2. Nothing runs unless you ask.

    No daemon, no timer, no hook and no shell alias is installed by default.

  3. Reading changes nothing.

    The read commands write no file and work on a machine that has never used yapacc before.

  4. Removable without trace.

    Delete the binary: everything it installed keeps working, and can be removed with native tools.

  5. Every change is gated.

    A plain command asks. --yes consents. --dryrun only plans. A refusal exits 3 and changes nothing.

  6. Changes go through your package manager.

    As the command it would run itself, shown in full, after its own simulation. The native log stays the record.

  7. A protection says what it does not protect.

    In the output, at the moment it matters, and not only in the manual.

§ 3How a change happens

Shown first. Simulated by the native manager. Then asked.

  1. Plan

    What will be installed, removed, upgraded or restored, and from where.

  2. Simulation

    The native manager's own dry run of that exact plan, printed as it says it.

  3. Gate

    You answer y, or you said --yes. Nobody to ask means no.

  4. Apply

    The native command, printed in full, run through sudo or doas.

  5. Record

    The native log. timeline and undo read it; yapacc keeps no second copy.

The same gate guards install, remove, upgrade and undo on all seven package managers. A snapshot can be taken before the change when the machine has snapper, timeshift or ZFS.

plain
shows the plan, asks [y/N]
--yes
consents in advance, for scripts you trust
--dryrun
plans and simulates, never applies
--script
never prompts; fails fast instead of waiting
exit 3
refused: you said no, or nobody could be asked

§ 5Install

One file. Read it, run it, delete it.

The core is a single static binary with no shared library. There is deliberately no curl | sh installer: you verify an archive and unpack it, or you build it.

Any Linux on x86_64 or aarch64. The archive holds the three binaries, the manual page and shell completions.

No root? Unpack into ~/.local instead of /usr/local. More in the handbook.

Rust 1.89 or newer. The portable core builds on any Linux and on FreeBSD; on Arch the default build also links libalpm.

Recipes for Arch, Debian and Ubuntu, Fedora and relatives, Alpine and Void are kept beside the source. They were built and installed in clean containers; none is in a distribution's repository yet.

§ 6Three ways in

For hands, for scripts, for assistants.

yapacc

The command line

Short verbs, plain sentences, and the command that would be run always printed. yapacc docs carries the manual offline.

--json · exit codes

Scripts

Read commands speak JSON. Seven exit codes tell a refusal from a failure from a missing tool, so a script never has to parse prose.

yapacc-mcp

AI assistants

An optional MCP server lets an assistant read and propose. It cannot apply a change unless you enable that in the configuration, whatever it claims about your approval.

§ 7What it is not

Small on purpose.

  • Not a package manager. It has no repository and no package format of its own. Yours does the work.
  • Not a backup. undo restores package versions, never your configuration or data.
  • Not a service. Nothing stays in memory, nothing wakes up at night, nothing phones home.
  • Not a configuration system. It does not manage dotfiles, services or the state of a fleet.
  • Not magic. When a tool is missing or an old version cannot be found, it says which and stops.
  • Not finished. Version {{version}} is a first public release. The limits are listed, not hidden.
