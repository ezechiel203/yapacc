Handbook · Reference

Configuration

yapacc needs no configuration. Without a file, the defaults below apply, and they are the safe ones: nothing is snapshotted or applied on its own.

Where the file lives§

~/.config/yapacc/config.toml, or $XDG_CONFIG_HOME/yapacc/config.toml. Another path can be given for one run with --config PATH. An XDG_CONFIG_HOME that is empty or not an absolute path is ignored, as the XDG specification says, and the same holds for the cache, state and data directories: yapacc never derives one of its paths from the directory you happen to be in.

prints the effective values and the file they were loaded from. yapacc never writes this file.

A file that does not parse, or a known key with an invalid value, is an error (exit code 2). yapacc does not fall back to defaults silently, because a protective setting that quietly stops applying is worse than a command that refuses to run. A section or key it does not know gets one warning line each, and yapacc config lists them, so a typo such as [safty] does not go unnoticed.

Paths in the file must be absolute or start with ~/.

The keys§

A complete example, yapacc.example.toml, ships with the source. The keys most people will want:

[safety]§

See snapshots.

[mcp]§

See AI assistants.

[build]§

For builds of third-party recipes (the AUR on Arch).

[repair]§

[install]§

[ledger]§

The ledger records what yapacc installed outside the native package manager (AppImages, flatpaks, isolated installs). Native packages are never recorded there; the package manager's own log is their record.

Environment§

VariableEffect
XDG_CONFIG_HOME, XDG_CACHE_HOME, XDG_STATE_HOME, XDG_DATA_HOMEwhere the configuration, caches, the ledger and data live
LC_ALL, LC_MESSAGES, LANGthe letters of the [y/N] question
NO_COLORhonoured by the interactive interface; the command line prints no colour codes

Command-line options that apply everywhere§

OptionEffect
--config PATHuse this configuration file
--jsonmachine-readable output on the read commands; goes before the command
--scriptnever prompt; fail fast instead
--noconfirmconsent in advance, like --yes
