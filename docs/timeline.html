yapacc timeline

yapacc timeline lists package installs, upgrades and removals, newest first, from the logs your package manager already keeps. It is read-only and it keeps no log of its own.

Each line is the time, the log it came from, what happened (install, upgrade, downgrade, reinstall, remove), the package and the version: old and new for an upgrade or a downgrade. dpkg's log calls every version change an upgrade; yapacc compares the two versions as dpkg does and says which it was. The downgrades above are an undo: it is a transaction like any other.

What changed since it last worked?§

--since-boot starts at the boot before the current one, because the question is usually "it worked yesterday, then I rebooted". The first line says which moment was used and where it came from, and a ── boot ── line marks where the machine restarted: what is listed below it was changed before the reboot. When only the current boot is known, a note says so and the list starts there instead.

The boot time comes from journalctl --list-boots where there is a journal, otherwise from the kernel (/proc/stat on Linux, sysctl kern.boottime on FreeBSD).

Options§

OptionEffect
--since YYYY-MM-DDonly changes on or after that day (UTC)
--since-bootonly changes since the previous boot
--limit Nat most N changes; the default is 50
--htmlwrite one self-contained HTML page to standard output

--html is meant for bug reports: yapacc timeline --html > timeline.html gives a single file with no external reference. It cannot be combined with --json.

Where the entries come from§

Package managerLog read
pacman/var/log/pacman.log
apt/var/log/dpkg.log, including rotated and compressed files
dnfdnf's own history database (dnf history)
zypper/var/log/zypp/history, including rotated and compressed files
apk/var/log/apk.log, when it exists
pkg (FreeBSD)/var/log/messages
xbpsnone: xbps keeps no log, and timeline says so

Some of these logs are readable by root only (openSUSE's /var/log/zypp is one). timeline then says which file exists and may not be read, tells you to run sudo yapacc timeline, and exits with code 6. yapacc platform marks such a log (exists; not readable by this user).

Times are printed as the log wrote them. A log that records local time without a zone (apt, zypper) is labelled (local). With --since-boot such a time is compared with the boot instant as if it were UTC, so a change made within your zone offset of the reboot can land on the wrong side of it; a note says so whenever it applies.

A log can be silent about a run. apk run with --quiet records that it ran and not what it did, and timeline then says how many runs it could not describe ("3 apk run(s) were logged without package details") instead of leaving them out without a word.

In a script§

ts is seconds since the Unix epoch. action is install, upgrade, downgrade, reinstall or remove; a reinstall has an empty old_version.
