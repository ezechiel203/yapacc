yapacc why

yapacc why NAME says why a package is installed, what still needs it, where it came from and how it was verified. It is read-only, and it answers for any package, whether or not yapacc had anything to do with installing it.

Reading the answer§

LineWhat it tells you
whatthe package's own one-line description
whythe reason it is installed; the wordings are listed below
becausethe chain back to a package you installed yourself; several lines when several of your packages lead to it
needed bythe installed packages that depend on it directly
fromthe repository it came from
installedwhen it was last installed or upgraded
verifiedhow the package manager checked it
packagerwho built the package, as the package records it
ledgerwhether yapacc itself has a record of installing it

The why line is one of these:

It saysMeaning
you (or a tool acting for you) installed it explicitlythe package manager has it marked as asked for
pulled in as a dependencysomething you installed needs it; because shows the chain
part of the base systemthe package manager protects it (Essential on apt), or the distribution gives it priority required
installed as a dependency, but nothing needs it any more (orphan)yapacc inspect orphans lists it, and yapacc remove orphans would remove it
installed as a dependency; nothing depends on it, but apt keeps itanother package recommends or suggests it, so apt-get autoremove leaves it alone
manager does not record an install reason herethe package manager has no such record for this package

The from line is never left empty. When the manager cannot say, the line says that: on apt, a package whose installed version has since been replaced in the index reads "the installed version is no longer in the repository index (a newer one is, from …)"; on zypper the line names the repository that offers the package now, because the zypp history does not record where the installed version came from.

When part of the answer could not be checked, the line starts with note: and says what was missing. yapacc does not guess.

Not every package manager records every fact, and a line that has no source is left out: apk records no install date, and FreeBSD's pkg has no verified line.

On a long needed by list the terminal shows the first few names and a count. --json lists all of them.

More than native packages§

why prints one block for each place that knows the name: the native package, a flatpak with a matching name, and anything yapacc installed itself outside the package manager (an AppImage, for example).

Exit codes§

CodeMeaning
0found, answer printed
2the name is not a valid package name
4not installed anywhere yapacc can see

In a script§

reason is explicit, dependency or unknown. orphan is true or false as the package manager's own orphan list says, null when that was not asked or is not known, and native.base is "essential", "priority required" or empty. --json goes before the command. See scripting.

Related§

  • yapacc inspect owns /usr/bin/env finds the package that owns a file.
  • yapacc inspect files NAME lists the files of a package.
  • yapacc inspect orphans lists dependencies nothing needs any more; yapacc clean reports how much space they take.
