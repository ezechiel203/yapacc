Handbook · Everyday commands

doctor and platform

Two read-only commands that describe the machine. Run doctor first on any new system, and attach both to a bug report.

doctor§

yapacc doctor prints one line per check: what works on this machine, what does not, and why.

StateMeaning
okit works
warnsomething a feature of this system uses is missing or weaker; the line says what you lose
faila command will not work until this is fixed; the line says why
n/athe check does not apply to this system, or an optional part (yapacc-tui, yapacc-mcp, flatpak, gpgv) is not installed; the line says what it would be for

A healthy machine shows ok and n/a only, as above.

The lines for undo, timeline and briefing say what each can do on this machine: where old versions would come from, which log is read, whether there is a news feed. A system without a package log gets "no timeline" here, not an empty timeline later.

yapacc --json doctor gives the same list as an array of {name, state, detail}.

platform§

yapacc platform says what kind of machine this is, one line per axis. Each axis is detected on its own; yapacc does not assume that a distribution implies an init system or a boot loader.

Where an axis could only be read in part, the line says so, as for the boot loader above. A package log that is there but closed to you is marked (exists; not readable by this user).

When a machine has several package managers installed, the native one is the one whose database owns /usr/lib/os-release. dnf and zypper read the same rpm database; between them it is the one that has repositories configured, and zypper on SUSE, dnf elsewhere, when both have. The other one is listed on an other managers line.

The last line is the support tier of the native package manager. What works where explains the tiers.
