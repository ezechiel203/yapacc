yapacc briefing

yapacc briefing tells you what the next upgrade will do before you run it. It is read-only: it reads the list of pending updates and reports what deserves attention.

The sections§

Needs attention sorts the pending packages by what they mean for you:

LabelMeaning
reboota kernel, C library or init system update: the new code runs only after a reboot. Kernels are recognised under the names each system gives them (linux-image-…, kernel-default, linux6.12, linux-lts, FreeBSD's FreeBSD-kernel-…)
carethe package manager itself, the boot loader or remote access is being updated: do not interrupt, and keep a second session open over ssh
infomajor version changes, worth a look at the release notes

Security fixes lists the pending updates that fix known vulnerabilities, where the system has a source for that: the security repository on Debian and Ubuntu (an update that several repositories offer counts when one of them is the security one), the advisory data of dnf and zypper, and arch-audit on Arch when it is installed. Where there is no source, a note says so instead of printing an empty list.

Distribution news shows recent announcements from the distribution's feed. Lines marked ! announce a manual step. This is the one part of briefing that uses the network (through curl); --offline skips it. Distributions without a machine-readable feed get a note saying so, as Debian does above. On Arch, which has one:

Configuration files still unmerged lists what earlier upgrades left for you to merge. yapacc configs shows how to compare each one.

Disk shows free space where packages are written.

Safety net says whether a snapshot tool is available and reminds you what undo does and does not restore.

It does not refresh§

briefing reads the pending list as of your last repository refresh (apt-get update, pacman -Sy, dnf makecache and so on) and says so in a note. A read command never refreshes repositories for you, and never lets the package manager do it behind your back: on dnf and zypper, where the native tool would fetch metadata on its own, yapacc asks it for cached data only. If the list looks old, refresh with your package manager, or run yapacc refresh, which is gated like any other change.

On a machine that has never refreshed (a fresh image, a new container) there is no pending list to read. yapacc says that, and names the command, instead of reporting that nothing is pending:

briefing then opens with "pending packages not known" and the same note. On Arch, when checkupdates is installed but fails, the briefing says the list below it is not current and why.

Options§

OptionEffect
--offlinedo not fetch the distribution's news feed

After the briefing§

yapacc upgrade runs the full upgrade through the native manager, with the plan and the gate. See install, remove, upgrade.
