Install

yapacc is one static binary. There are three ways to get it: a release archive, a build from source, or a distribution package you build from the recipe kept beside the source.

There is deliberately no curl | sh installer. A tool whose job is to show you what will happen before it happens should not start by asking you to run something you have not read.

Release archive (any Linux, x86_64 or aarch64)§

Each release publishes one archive per architecture and a SHA256SUMS file. The binaries are linked statically against musl: they need no shared library and run on any Linux distribution.

What is in the archive§

Path under the prefixWhat
bin/yapaccthe command line
lib/yapacc/yapacc-tuithe optional interactive interface (yapacc i)
lib/yapacc/yapacc-mcpthe optional server for AI assistants (yapacc mcp)
share/man/man1/yapacc.1the manual page
share/bash-completion/, share/zsh/, share/fish/shell completions
LICENSE, README.mdthe licence and the readme

Only bin/yapacc is required. Delete the other two binaries if you do not want them; yapacc doctor then reports them as optional components that are not installed.

Note

The alpm feature uses a Rust crate published under GPL-3.0, while yapacc is GPL-2.0-only. It is there for local builds on Arch. No release archive or packaging recipe enables it, and everything in this handbook works without it.

Distribution packages§

Recipes for five distributions live in contrib/packaging. They are not in any distribution's repository yet; you build the package yourself and install it with your package manager, which then owns the files.

DistributionRecipeBuild
Arch Linuxarch/PKGBUILDmakepkg -si
Debian, Ubuntudebian/dpkg-buildpackage -us -uc -b
Fedora and relativesrpm/yapacc.specrpmbuild -ba
Alpine Linuxalpine/APKBUILDabuild -r
Void Linuxvoid/template./xbps-src pkg yapacc

The packaging README has the details for each, including which Rust version the distribution needs.

Uninstall§

yapacc installs no service, no hook and no timer, so removing it is removing its files.

  • Archive: delete bin/yapacc, lib/yapacc/, the manual page and the three completion files from the prefix you unpacked into.
  • Package: remove it with your package manager.

Files yapacc may have created under your home directory, all safe to delete:

PathWhat
~/.config/yapacc/your configuration file, if you wrote one; yapacc never writes it
~/.cache/yapacc/build caches, and downloads of an undo while it runs
~/.local/state/yapacc/the ledger of installs made outside the package manager
~/.local/share/yapacc/AppImages, recipes and isolated installs, if you used those commands

Native packages installed or upgraded through yapacc belong to your package manager and are not affected.
